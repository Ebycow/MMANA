# 保証一覧

計算エンジン（`mmana-core`）と HTTP API が**何を保証しているか**と、それを確かめているテストの一覧です。
テストの件数ではなく、どの性質・境界・組み合わせを保証しているかで品質を判断するための資料です。

目標は次の 1 文です。

> どんな入力でも「明確に拒否される」か「性質を満たす結果が返る」かのどちらかになる。旧版と違う箇所は、すべて意図して変えたものである。

バグが見つかったときは、まずこの一覧のどの行が破れていたのかを確かめます。どの行にも当てはまらなければ、
一覧に行を足してから直します（足した行には必ずテストを対応させます）。

## 入力の範囲

すべての計算は `validate::project`（[validate.rs](../crates/mmana-core/src/validate.rs)）を通ります。
`calculate`・周波数特性・遠方界・近傍界・最適化は `solve` から、パルス配置は `pulse_layout` から呼ばれ、
どちらも最初にこの関数で入力を確かめるので、同じ入力が入口によって通ったり拒否されたりすることはありません。
例外は、パルス配置が給電点・負荷・重なったワイヤを確かめないことだけです（編集中でも配置を表示するため）。

範囲は、デスクトップアプリの入力欄の範囲と、エンジンが値に意味を持たせられる範囲に合わせています。
JSON・API・`.maa` の数式（`1e999` は無限大になる）・最適化の試行からは、入力欄の範囲外の値も届きます。

| 項目 | 受け付ける範囲 | 範囲外のとき |
|---|---|---|
| 計算周波数（設計周波数、`options.frequencyMhz`） | 有限で 0 より大きい | `InvalidFrequency` |
| 水平パターンの仰角（`options.horizontalCutElevationDeg`） | −90〜90° | `OutOfRange` |
| パルス数（`options.maxPulses`、最大 8192） | 分割した結果がこの数以下 | `TooManyPulses`（配列を確保する前） |
| ワイヤ | 1 本以上 | `NoWires` |
| ワイヤの半径 | 有限（負の値は組み合わせワイヤの指定、0 は無効なワイヤ） | `OutOfRange`。組み合わせワイヤがなければ `CombinedWireNotFound` |
| R ≠ 0 のワイヤの座標・長さ | 有限。長さが 0 でない | `OutOfRange`、`ZeroLengthWire` |
| R ≠ 0 のワイヤどうし（計算のみ） | 両端が一致するワイヤがない | `OverlappingWires` |
| 自動分割 | DM1・DM2 ≥ 1、SC 1.01〜3、EC ≥ 1 | `InvalidAutoSegmentation` |
| ワイヤの分割数 | 固定分割数 ≥ 1。個別テーパの DM は 1〜32767（DM2 なしの DM1 は 1〜10000） | `InvalidSegmentCount`、`InvalidWireSegmentation` |
| 組み合わせワイヤ | キーが有限。区間の長さ・半径が有限で 0 以上（長さ 0 は区間の終わり、半径 0 は前の区間と同じ） | `OutOfRange` |
| スタック | 横・縦の個数 ≥ 1。個数が 2 以上の向きの間隔と、間隔 ×（個数 − 1）が有限 | `OutOfRange` |
| スタックの規模 | 個数 × R ≠ 0 のワイヤ本数 ≤ 4096 | `TooManySegmentWires`（コピーを作る前） |
| 展開ワイヤ（テーパ・組み合わせワイヤで分かれたワイヤ） | 4096 本以下 | `TooManySegmentWires` |
| 給電点（計算のみ） | 1 個以上。電圧・位相が有限。電圧のどれかが 0 でない。名前が解決できる。2 つが同じパルスにない | `NoSources`、`OutOfRange`、`NoExcitation`、`PulseOutOfRange`、`DuplicateSource` |
| パルス名 | 番号・ワイヤ番号・オフセットが 2147483647 以下 | 解決できない名前として扱う |
| 負荷（有効なときの計算のみ） | 値が有限。L・C の両方が 0 ではない。S パラメータ形式は 12 項以下で、分母の係数のどれかが 0 でない。名前が解決できる | `OutOfRange`、`InvalidLoad`、`PulseOutOfRange` |
| SWR 基準 | R は有限で 0 より大きい。X は有限 | `OutOfRange` |
| F/B の後方範囲 | 水平 0〜360°、垂直 0〜180° | `OutOfRange` |
| 地上高（大地ありのとき） | 有限 | `OutOfRange` |
| 実大地（実大地のとき） | 媒質が 1 つ以上。誘電率は有限で 0 より大きい。導電率は有限で 0 以上。境界・高さは有限 | `NoGroundMedia`、`OutOfRange` |
| ラジアル（実大地のとき） | 本数 ≥ 0。本数が 1 以上なら半径は有限で 0 より大きい | `OutOfRange` |
| 遠方界・近傍界の軸 | 始点・刻み・最後の点が有限、個数 ≥ 0（0 と刻み 0 は 1 点） | `OutOfRange` |
| 遠方界・近傍界の点数 | 1,000,000 以下（`MAX_FIELD_POINTS`。桁あふれしない飽和演算で数える） | `TooManyFieldPoints`（確保する前） |
| 近傍界の電力 | 有限で 0 より大きい。アンテナの入力電力も 0 より大きい | `OutOfRange`、`NonPositivePower` |
| 周波数特性の点数・指定した点の数 | 1〜100,000（`MAX_SWEEP_POINTS`） | `InvalidSweepPoints`（確保する前） |
| 周波数特性で指定した点 | 点数未満 | `SweepPointOutOfRange` |
| 上の範囲内でも解が有限にならない（間隔 0 のスタック、負荷の共振など） | — | `NoFiniteSolution` |
| 上の範囲内でも、結果（f32 で持つ表示用電流・パターンを含む）や走査の値が表せない大きさになる（電圧 1e100、近傍界の電力 1e308 など） | — | `NotRepresentable`（返す前にすべての値を確かめる） |

どの行も、境界上の値が通ること、すぐ外の値が拒否されること、`calculate` と `pulse_layout` の判定を
[input_ranges.rs](../crates/mmana-core/tests/input_ranges.rs) で確かめています。
上限を超えた入力が大きな確保より前に拒否されることは [allocation.rs](../crates/mmana-core/tests/allocation.rs)
（最大の確保が 1 MB 未満であること）で確かめています。

### HTTP API の上限

API は計算を始める前に、サーバーの設定（`mmana_api::Limits`）による上限を確かめます。どれもエンジンの上限以下です
（`server_limits_are_within_the_engine_limits`）。上限を超えると 422 `limit-exceeded`、エンジンが拒否した入力は 422 `calculation-failed` で、
どのエンドポイントに送っても同じ問題として返ります（`an_invalid_input_is_rejected_alike_by_every_endpoint`）。

| 項目 | 既定値 | 超えたとき |
|---|---|---|
| `options.maxPulses` | 4096 | 要求の値をこの値まで下げて計算する（パルス数が超えれば `TooManyPulses`） |
| 周波数特性の点数・指定した点の数 | 401 | `limit-exceeded` |
| 遠方界の方向数・近傍界の点数 | 65,341 | `limit-exceeded` |
| エレメント編集・最適化の設定編集の（操作数 + 1）× ワイヤ数 | 1,000,000 | `limit-exceeded` |
| 最適化 1 回の計算回数 | 2000 | その回数で打ち切り、それまでの最良値を返す |
| リクエストの大きさ | 4 MB | 413 |

| 計算エラーと警告は、種類（`code`）と対象のワイヤ番号（定義した番号。スタックのコピーはコピー元）を持つ。API・Tauri・wasm のエラー本文にも載る | 重なったワイヤ、長さ 0、分割しすぎた導体（離れたワイヤを含めない）、地面より下のワイヤ（スタックあり・なし） | validation.rs の `errors_name_the_wires_they_are_about`、properties.rs の `warnings_name_the_wires_they_are_about`、API・wasm の `calculation_errors_name_their_wires` |

**任意のモデル**は、ワイヤ 1〜5 本（端点は 70 % が格子点で接続が起きやすい、R = 0 と組み合わせワイヤを含む、6 種の分割方法）、
任意の書き方の給電点 0〜3 個と負荷 0〜2 個（存在しない名前・番号、全角を含む）、スタック、3 種の大地、7 種の材質です。
多くは拒否されるので、成功経路は**組んだモデル**で確かめます。**壊れた `.maa`** は、サンプル 81 件の行を消す・重ねる・途中で切る・挿入する、
欄を `1e999`、`99999999999`、`nan`、`1/0`、セクションの見出しなどに差し替えたものです。

自動生成は `cargo test` で 256 件ずつ、夜間の CI（[quality.yml](../.github/workflows/quality.yml)）で 20,000 件ずつ試します。
見つかった失敗は `random_models.proptest-regressions` に保存され、次回から最初に再実行されます。
原因がわかったら、小さな再現ケースにして通常のテストに移します（下の「見つかった問題」の行がその例です）。

## エレメント編集と最適化

計算エンジンと同じく、ランダムな操作の列で確かめています。テストは [random_edits.rs](../crates/mmana-core/tests/random_edits.rs) と
[random_optimize.rs](../crates/mmana-core/tests/random_optimize.rs) のものです。`cargo test` で 256 件ずつ、夜間の CI で 20,000 件ずつ試します。

| 要求する性質 | 確かめた入力 | テスト |
|---|---|---|
| 編集の列のどこでも panic せず、20 秒以内に終わる。受け付けた編集のあとの寸法・位置・ワイヤはすべて有限 | サンプル 81 件と格子上のワイヤ 0〜6 本に、ランダムな行（「新規」行とその先を含む）への編集 0〜7 個。値は表示中の値の 0.2〜5 倍・±3 m、または 0、−1、1e-300、1e300、`f64::MAX`、NaN、±∞。形式の作り替え・挿入・削除・値を丸める（0〜11 桁、m・mm・波長） | `any_element_edits_…` |
| 拒否した編集は何も変えない：拒否されたものを除いて再生しても同じ結果になる（デスクトップの「元に戻す」は操作の列からの再生で、拒否された操作を列から除く）。編集がなければアンテナはそのまま | 同上 | 同上 |
| 表の寸法と位置は、書き戻したワイヤの範囲と一致する（10 ppm、最低 0.01 mm） | 同上のうち、開いたときに表がワイヤと一致しているアンテナ | 同上 |
| 給電点・負荷のワイヤ名は存在するワイヤを指す | 同上 | 同上 |
| 元の値を入れ直すと元のエレメントに戻る（戻らない形になる場合は拒否される。0 をまたいだ端と、縦横比の違う八角形の全周は、オリジナルどおり戻らない：[移植メモ](porting-notes.md)） | 同上の編集のあと、寸法・間隔・位置・半径を 0.5〜2 倍してから元の値を入れる | `a_value_typed_back_…` |
| 計算できるアンテナを常識的に編集しても計算でき、結果は有限。入力電力が正でなければ警告が付く。給電点・負荷の名前は変わらない | 計算できるサンプル（1500 パルス以下）に、寸法・間隔 0.8〜1.25 倍、半径 0.5〜2 倍、分割 5〜21・自動・テーパの編集 1〜5 個（分割を減らして `w1c-8` のような位置がなくなったときの `PulseOutOfRange` は可） | `sensible_edits_…` |
| 最適化は panic せずに終わり、評価値はすべて有限。最良の評価値は全試行の最大で、開始値以上。改善の印が付いた評価値は増え続ける | 2〜4 素子の八木と 120 パルス以下のサンプルに、設定の編集 1〜6 個（変数の設定・全エレメント・自動連携・挿入・削除）で作った変数、ランダムな重み・目標・ピッチ（0.1〜5 倍）・バンド・開始周波数・単純スイープ。計算 40 回まで | `an_optimisation_…` |
| 最後のアンテナは最良の試行を書き戻したもので（1 ppm）、計算すると最良の試行の値になり、入力電力の警告が付かない（計算が失敗して止まったときも） | 同上 | 同上 |
| 一覧の各試行を `apply_trial` で書き戻して計算すると、一覧の値になる（\|Z\| の 0.1 %、\|Γ\| の 0.001、利得・F/B 0.05 dB）。入力電力の警告が付く試行は評価値が最低 | 同上 | 同上 |

試行は値を 1 歩ずつ設定し、書き戻しは一度に設定するので、座標の丸めが違います。不規則なエレメントの寸法を何度も拡大縮小するとこの差が積み上がり、
Feeder TEST では計算 850 回で \|Z\| の 0.015 % になります。許容誤差はその上で、模型と実物の差（共振周波数で 1 % 程度）より十分小さく取っています。

旧版との一致は、エレメント編集は旧版の規則だけで適用する `apply_as_original` で、最適化は拒否・折り返しの起きない金型の設定で確かめます。
金型のうち `SLOPER_polar` は、旧版の設定（上端を固定した天頂角と中央を固定した長さ）が動かした順でアンテナの変わる組だったので、両方とも上端を固定する設定に変え、
中央を固定した長さは `SLOPER_polar_centre` で単独で確かめています。

## 正しさ（旧版に頼らない性質）

[properties.rs](../crates/mmana-core/tests/properties.rs) で確かめています。2 倍・名前の付け替え・並べ替えのように浮動小数点で誤差の出ない変更は
**ビット単位で一致**することを、それ以外は理由を添えた許容誤差の範囲で一致することを求めます。

| 入力の変え方・法則 | 成り立つべき性質 | 許容誤差 |

| SWR | インピーダンスと基準値からの式どおり | 相対 1e-6 |
| 給電点・負荷を名前と番号で指定（スタックありも） | 同じ結果 | ビット一致 |
| パルス配置の名前のどれで給電しても | そのパルスへの給電 | ビット一致 |
| スタック | コピーを手で並べ、電圧を分けたものと同じ | ビット一致 |

| 0 Ω の負荷を足す | 負荷なしと同じ | ビット一致 |

| 順番を変えて、別スレッドで同時に計算する | 前後・並行の計算に左右されない | ビット一致 |
| 損失なしのアンテナ（自由空間・完全導体大地） | 全天球での放射電力の積分 = 入力電力 | 2 %（MININEC 自体が 0.2 % ほど少ない） |

## 検証コードのテスト

`cargo mutants` で検証コード（[validate.rs](../crates/mmana-core/src/validate.rs)、パルス名の解決）をわざと壊し（`<` を `<=` に、チェックを削除、など）、
テストが失敗することを確かめています。2026-10-22 の時点で、261 個のうちビルドできない 2 個を除くすべてを検出しています。
最初の実行で見逃した 9 個と、その後に足した結果・軸・スタックのチェックで見逃した 15 個は、境界値のテストを足すか、冗長な判定を消して直しました。
有限の入力からは起こせない結果の非有限値は、単体テストで直接入れて確かめます。

夜間の CI では、検証コードに限らず mmana-core 全体（約 7,300 個）を 14 夜に分けて壊します。第 n 夜は番号を 14 で割った余りが n のもの（約 520 個）で、
6 つのジョブに分けて実行するので、どのミュータントも 2 週間に 1 回実行されます。特定の夜の分は、手動の実行で `night` に 0〜13 を指定して実行できます。
テストが時間切れになったものは検出とみなし、見逃したものがあればジョブが失敗します（`mutants.out` の `missed.txt` に一覧があります）。

第 0 夜（2026-10-25、519 個）は 75 個を見逃しました。27 個は境界値・テンプレートの形・エディタの変数登録などの単体テストを足して、
23 個は golden で検出するようにしました。golden には、サンプルが通らない計算の経路のモデル（`testdata/models`：テーパーの片端、
組み合わせワイヤの各型、±45° で大地に接する斜めのワイヤとその近傍界、160 m の細い銅線、分母に奇数次のある s 領域の負荷）と、
媒質 2 つの実大地・ラジアルを足しています。移植はそのすべてでオリジナルとビット単位で一致しました。
残る 25 個は結果を変えない等価ミュータントで、どこからも届かない分岐や冗長な判定は消し、消せないものは理由を書いて
[`.cargo/mutants.toml`](../.cargo/mutants.toml) で除外しています。golden を許容誤差だけで比べる（Linux の CI と同じ）条件でも、
直したものはすべて検出されます。

第 4 夜（2026-10-26）と第 5 夜（2026-10-27）は合わせて 91 個を見逃しました（第 4 夜は 2 つのジョブがランナーの停止で途中で終わり、その分は未実行）。
37 個は境界値・リンク・全エレメント登録・刻み幅などの単体テストを足して、15 個は golden で検出するようにしました。golden には、
3 軸に斜めの組み合わせワイヤ（銅線）、細い銅パイプ・鉄線の損失、145 MHz の s 領域の負荷（使わない係数の項が丸めで消えない周波数）、
端の分割数が 3 のテーパー、終端どうしで 1 点に集まる 3 本のワイヤ、近傍界の格子点の 1 cm 横を通るワイヤのモデルを足しています。
13 個はどこからも届かない分岐（`AdjPdef` が必ず 99999.9 m の区間で終えるので長さ 0 の区間に届かない、1 本分の長さで割った後の判定）や、
二乗で消える符号・0 のときの場合分け・入力電力の判定の二重の実装を消して、なくなりました。残る 26 個は等価ミュータントで、理由を書いて除外しています。

第 4 夜の再実行と第 6 夜（2026-10-28）は、合わせて 43 個を見逃しました（第 4 夜は前回から番号がずれ、別のミュータントの組です）。

第 6 夜の 2 つのジョブは、ランナーごと止まって途中で終わりました。数式の読み取りで文字の位置が進まなくなるミュータント
（`Parser::at` が常に 1、`p += 1` が `p *= 1`）が、終わらないループで確保を続け、ランナーのメモリを使い果たしたためです。
夜間の CI では mutants のステップのアドレス空間を 8 GB に制限し（`ulimit -v`）、そうしたミュータントは確保の失敗で検出として数えます。

上限が壊れたときのテストは、数 GB の確保や終わらない計算になります。そうした入力は [allocation.rs](../crates/mmana-core/tests/allocation.rs) と

ただし上のように、ミュータントそのものが終わらない確保になることがあり、macOS には `ulimit -v` が効きません。
`cargo mutants` を手元で実行するときは `-j 1` か `-j 2` にして、ループの条件・刻みや文字列の読み取りを壊すものは避けてください。

## 既知の限界

- **1 つの導体を細かく分けすぎたときの精度低下（旧版由来、警告あり）。** つながった 1 つの導体の分割数がおよそ 250 を超えると、
  分割を増やすほど結果がずれていきます（14.05 MHz の半波長ダイポールで、320 分割では X が約 6 Ω、640 分割では約 25 Ω）。
  効くのは導体ごとの分割数で、分割長と波長の比や線径にはほとんどよりません（0.1λ のダイポールは λ/2560 の 256 分割でも安定）。
  1 本を何本のワイヤに分けても同じで、離れた導体どうしは足し合わされません。オリジナルの C++ でも同じ値になり、
  行列を f64 にしてもずれは半分ほどにしか減りません。直すとオリジナルとのビット一致がなくなるため、計算結果に警告を出します
  （`a_conductor_divided_too_finely_is_warned_about`。サンプルでは、分割数で値が動く CR2 と LPDA の 2 件に出ます）。
- **つながったワイヤーの横の点を、ワイヤー上の点として計算してしまう（旧版由来、警告あり）。** MININEC は、観測点に近い区間を
  同じワイヤー上の点として近似しますが、「同じワイヤー」の判定が接続点を共有しているかだけなので、つながった別のワイヤーが区間の横を
  通っていると、その上の点にも近似を使います。折り返しダイポールでは区間の長さが間隔の 4.36 倍を超えると共振が +6〜16 % ずれ、
  給電点の抵抗が 286 Ω から 1.7〜14 Ω になります。約 27° より鋭い V の頂点でも同じことが起きます。直すとオリジナルとのビット一致が
  なくなるため、計算結果に警告（`CloseWires`）を出します（[測定](measurements/README.md#closewiresつながったワイヤーの横の点をワイヤー上の点として計算している)）。
- **`currentDisplay` はオリジナルの表示用の配列そのもの**で、最後に値を入れたパルスで終わるため、ループの最後のパルスが欠け、
  値のないパルスは 1.2345e-37 になります。全パルスの電流は `currents` にあります。


## 対象外

- 実測値や NEC2 などとの絶対精度の比較（標準的なアンテナ数本での確認は今後の課題）
- デスクトップアプリの UI の動作（ワイヤー編集のコマンドと「元に戻す」は上記のとおり確かめています）
- 性能（「時間内に終わる」こと以外）
