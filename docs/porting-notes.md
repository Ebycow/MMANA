# 移植メモ：オリジナルとの意図的な違い

正しい入力に対する計算結果は、オリジナルと完全に一致します。
違いがあるのは、オリジナルが不正な状態のまま計算を続けていた箇所と、ファイル保存時の欠落だけです。

## 計算

| 状況 | オリジナル | 移植版 |
|---|---|---|
| 給電点が 0 個 | 存在しない給電点で計算し、意味のない値を出す | エラー `NoSources` |
| 給電点のパルス名が解決できない（`w99c` など） | パルス 0 として計算を続ける | エラー `PulseOutOfRange` |
| 組み合わせワイヤの定義が見つからない | 警告を出し、そこで展開を打ち切って計算を続ける | エラー `CombinedWireNotFound` |
| 自動分割の SC が 1 以下、DM1・DM2 が 0 以下、EC が 0 以下（JSON・API からのみ入力できる） | 画面と .maa 読み込みでは範囲内に補正されるが、そのまま計算すると分割処理が終わらない | エラー `InvalidAutoSegmentation` |
| ワイヤ個別テーパの DM が 1〜32767 の範囲外（DM2 なしの DM1 は 1〜10000） | DM2 が 0 だと分割処理が終わらない | エラー `InvalidWireSegmentation` |
| 固定分割数が 0 以下（JSON・API からのみ入力できる） | SEG の値として自動分割やテーパの指定に読み替えられ、DM2 が 0 になる値では分割処理が終わらない | エラー `InvalidSegmentCount` |
| 展開ワイヤが 4096 本を超える | 超えた分を黙って捨てる | エラー `TooManySegmentWires` |
| 両端が完全に一致するワイヤが 2 本ある（向きは問わない。R = 0 の無効なワイヤは除く） | インピーダンス行列が特異になり、電流・インピーダンスが NaN のまま計算を続ける | エラー `OverlappingWires`（ワイヤ番号を示す） |
| それ以外の理由で解が有限にならない（間隔 0 のスタックなど） | 同上 | エラー `NoFiniteSolution`。最適化中の試行でこうなったときは、そこで最適化を終える |
| パルス数の既定上限 | 1280（INI で変更可） | 4096（`CalcOptions.maxPulses`、上限 8192） |
| 近傍界（磁界）の計算後 | 実大地の媒質の高さを格納する配列を作業領域として上書きしてしまう | 配列を分けたので影響なし |
| 連続計算 | 前回の計算のパターン配列などが残る | 計算ごとに新しい状態で始める |

## ファイル（.maa）

| 項目 | オリジナル | 移植版 |
|---|---|---|
| 数式の `R`（波長） | 読み込み時は常に 14.05 MHz の波長になる（初期化順の都合） | そのファイルの設計周波数の波長 |
| 設計周波数の小数点以下 4 桁目以降（手で編集したファイルなど） | 読み込み時に画面表示（`%.3lf`）を経由するため、0.001 MHz 単位に丸めて計算・保存する。DP20 を 14.05049 MHz にすると 77.627 − j5.341 Ω | 丸めずに計算・保存する。同じファイルで 77.632 − j5.292 Ω |
| SWR 基準の jX の保存 | `%.lf` で小数点以下を切り捨てて保存 | 小数も保存（読み込みは互換） |
| ワイヤ・給電点・負荷の数 | 512 / 64 / 100 で打ち切り | 制限なし（計算時の上限は上表のとおり） |
| パルス名の末尾の空白 | 名前の一部として扱い、解決に失敗することがある | 取り除く |
| 実大地の媒質・ラジアル | 保存しない（`Mmana.ini` に保存） | 既定値から変えたときはコメント欄に保存（下記） |
| ファイルの文字コード | Shift_JIS のみ | Shift_JIS と UTF-8 を自動判別。保存は Shift_JIS が既定 |

## エレメント編集

書き戻すワイヤの座標・半径・分割数はオリジナルと完全に一致します。違いは書き戻した後の扱いと、上限・表記だけです。

| 項目 | オリジナル | 移植版 |
|---|---|---|
| ワイヤ番号が変わったときの給電点・負荷 | パルス名（`w3c` など）をそのまま残すので、別のワイヤを指すことがある。削除で空いた番号に新しいワイヤが入ると、そのワイヤに付く | ワイヤに追従して番号を書き換える。削除したワイヤ上のものは、空いた番号に別のワイヤが入っても引き継がず、取り除いて警告を出す。形式を作り替えたエレメントでは、古い k 本目のワイヤ上のものが新しい k 本目に移る（新しい形のワイヤが少なければ、余った分は取り除いて警告）。電圧自動設定が有効なら、給電点を取り除いたあと各電圧を 1 / 給電点数 にそろえる（給電点の削除と同じ扱い） |
| パルス番号（`15` など）で指定した給電点・負荷 | そのまま | そのまま。番号がずれうるので警告を出す |
| エレメント数 | 256 で打ち切り（グループ番号を 1 バイトで持つため、それ以上は誤動作する） | 制限なし（API は「(操作数 + 1) × ワイヤ数」を 100 万までに制限） |
| 水平△・水平▽ の作り替え | メニューの「水平▽」は、形式表で「水平△」と呼ぶテンプレートで作る（できた形は ▽ と判定される） | 作られる形で呼ぶ（`horizontalInvertedTriangle` を指定すると ▽ と判定される形になる）。同じ形式かどうかの判定はオリジナルと同じくテンプレートで行う |
| CSV ファイル | Shift_JIS。Seg. の `400,40` を引用符で囲まないので列がずれる | UTF-8（BOM 付き）。カンマを含む値は引用符で囲む |
| 同一エレメントの確認 | OK を押したときに警告 | 編集のたびに確認し、重なっている間は「反映」を押せない |

オリジナルの次の動作は、結果を変えないようそのまま再現しています。

- ループの判定は、意図とは違い常に 1 本目のワイヤから始まる（最長のワイヤを探す処理が働いていない）
- 「全ての座標を同一比率で変更」は、エレメントの中心ではなく原点を基準に拡大・縮小する
- 「値を丸める」で半径が 0 に丸まると、mm 表記では小数点以下 2・3・4 桁でそれぞれ 10 m・1 m・0.1 m になる（1/1000 の付け忘れ）
- 「新規」の行で形式を選んで作ったエレメントの間隔は 0（前に削除したエレメントの間隔が残っていればその値）になる
- 何も変更せずに OK したときは書き戻さない（書き戻すと X 座標に丸め誤差が入るため）

ダイアログのうち「電卓」（数値欄で数式が使えるので不要）、「印刷」（印刷は今後の対応）、「組み合わせワイヤ設定」（編集画面が未移植）は移植していません。
最適化用の変数選択モード（`TGrpWireDlg::Select`）は、最適化の変数表の「位置」「箇所」のメニューに置き換えました（エレメントの形式も表示します）。

## 最適化

試す値の順序、評価値、試行の記録、最終的なアンテナはオリジナルと完全に一致します（バンドが 2 つまでの場合）。違いは次のとおりです。

| 項目 | オリジナル | 移植版 |
|---|---|---|
| 3 バンド以上の評価値の合算 | 2 番目以降のバンドの代わりに最後のバンドの評価値を足す（`BV[b]` を `BV[bb]` と書くべきところ）。2 番目から最後の 1 つ手前までのバンドは評価されない | すべてのバンドを足す。2 バンドまでは同じ値 |
| 複数バンドで最適化した後の給電点と計算周波数 | 最後に計算したバンドのまま残る | 最適化前の給電点と計算周波数に戻す（周波数・給電点を変数にした場合はその最良値） |
| 最適化結果の一覧から反映（更新） | いまのアンテナからエレメントを解析し直して値を当てはめる。試行でエレメントの並びが変わっていると（間隔を負にして別のエレメントの後ろへ回したなど）、別のエレメントに当てはまる | 最適化を始めたときのアンテナと計算条件に当てはめる（その後の編集は失われる） |
| 最適化結果の一覧のパターン | 最後に計算したバンドのもの。1/256 dB の固定小数点 | 1 番のバンドのもの（一覧の数値と同じバンド）。`float` のまま |
| S パラメータ形式の集中定数を変数にする | エラーを表示するが、そのまま最適化する | 実行しない（`sDomainLoad`） |
| 存在しない変数への連携・`#n` | 連携は変数 1 などに黙ってつながる（未使用の行の内容による）。`#n` は配列の外を読む | 実行しない（`missingVariable`） |
| 給電点の変数が、給電点の少ないバンドにない | 給電点配列の使われていない領域に書き込んで続ける | 実行しない（`bandMissingSource`） |
| 存在しないワイヤ（極座標）・給電点を変数にする | 確認せずに配列の外を読み書きする | 実行しない（`missingTarget`） |
| 1 回も試行が終わらないうちに中止・計算エラーになった | 最良値の代わりに「開始値の符号を反転した値」をアンテナに書き込む | アンテナを変えない |
| 実行時に開始値を Min / Max に収める（`Check`） | 前回の実行の歩幅が残っていると、境界から歩幅だけ内側に収める | 常に最初の実行と同じ（境界そのもの）。設定がアプリの中だけにあり、前回の歩幅を持ち越さないため |
| 変数の挿入・削除 | 連携の番号は付け替えるが、Min / Max の `#n` は付け替えない | `#n` も付け替える（削除した変数を指していたものは数値の Min / Max に戻る） |
| 「全エレメント」で作る変数 | 前に使っていた行の `#n` が残ることがある | 残らない |
| ピッチ 0 の単純スイープ（ピッチが小さすぎて値が変わらない場合も） | 最大値に届かないまま同じ値を記録から読み続け、止まらない（中止もできない） | 値が動かない一歩を最大値・最小値に届いたものとして扱い、開始値を 1 回計算して終わる |
| 地中に埋まるワイヤ | 試行のたびに中止するか尋ねる | 続ける（計算結果に警告が付く） |
| スタックしたアンテナの電流目標 | 展開前のアンテナのパルス番号で、展開後の電流配列を読む | 展開後のアンテナで解決する（`w1c` は 1 つ目のコピー） |
| 最適化シート（`.mao` 相当のバイナリファイル） | 保存・読み込みできる | 未対応。設定はファイルを開き直すまでアプリが保持する |
| 実行中のログ | すべての計算を 1 行ずつ表示 | デスクトップアプリは評価値が上がった計算をすべて、それ以外を 40 ms ごとに表示。ブラウザ版は終了後の一覧のみ |

オリジナルの次の動作は、結果を変えないようそのまま再現しています。

- 連携が連携先を経由して続くときは、最後に到達した独立変数に、自分の連携式だけを適用する（途中の連携式は使わない）
- ワイヤの X 座標（X1, X2）の変数は、最初のエレメントが見つかった位置から数えた位置に足す（最初のエレメントが動くとずれる）
- ワイヤの座標を変数にしても、エレメントの境界は解析し直さない（同じエレメントの寸法の変数は、元の境界を使い続ける）
- 目標なし（単純スイープ）は、各変数を現在値から最大値まで動かしたあと、現在値から最小値までも動かす。評価値はすべて −0.1
- 複数バンドのとき、周波数の変数は 1 番のバンドの周波数を変える。給電点の変数はバンドの給電点で上書きされるので効かない
- 試行の記録は直近 128 件で、同じ値の組み合わせが記録にあれば計算せずにその評価値を使う

## 計算環境の値

実大地の媒質（誘電率・導電率・境界・高さ）とラジアル設定は、オリジナルでは `.maa` ではなく `Mmana.ini` に保存されています。
このため、オリジナルでは同じファイルでも PC ごとに計算結果が変わりえます。
移植版では `Environment.realGround` に持たせ、既定値はオリジナルと同じ（誘電率 5、導電率 0.001 S/m、媒質 1 つ）です。

既定値から変更した場合は、`.maa` のコメント欄の末尾に次のブロックとして保存します（ワイヤのメモの `[MMANA-WIRE-NOTES]` と同じ方式です）。

```
[MMANA-REAL-GROUND]
medium=誘電率,導電率,境界,高さ
screen=ラジアル本数,ラジアル半径
[/MMANA-REAL-GROUND]
```

- `medium` は媒質ごとに 1 行です。境界・高さは未設定なら空欄にします。`screen` はラジアルを使うときだけ書きます。
- 既定値のときはブロックを書かないので、オリジナルが書くファイルと同じ内容になります。
- 移植版は読み込み時にブロックを取り除き、値を計算環境に戻します。読めないブロックや閉じていないブロックはコメントのまま残し、警告を出します（大地は既定値になります）。
- オリジナルで開くと、ブロックはコメントの文字として表示されます。計算には使われず、オリジナル自身の INI の値で計算されます。
