# 移植メモ：オリジナルとの意図的な違い

計算エンジン・エレメント編集・最適化は、オリジナルとの一致を Oracle テストで検証しています。
検証範囲とプラットフォームごとの比較方法は [アーキテクチャ](architecture.md#検証の仕組みoracle-テスト) を参照してください。
この資料では、不正入力の扱い、ファイル入出力、編集後の給電点・負荷の追従、複数バンドの最適化など、
互換性より修正・改善を優先した箇所と、再現した旧版の動作をまとめています。
画面や保存機能を含む実装状況は [移植状況と残作業](architecture.md#移植状況と残作業) に記載しています。

## 計算

| 状況 | オリジナル | 移植版 |
|---|---|---|
| 給電点が 0 個 | 存在しない給電点で計算し、意味のない値を出す | エラー `NoSources` |
| 給電点の電圧がすべて 0 | 電流が 0 になり、インピーダンス・SWR が 0 ÷ 0 の NaN のまま結果を出す | エラー `NoExcitation`（パルス配置の取得はできる） |
| 給電点のパルス名が解決できない（`w99c` など） | パルス 0 として計算を続ける | エラー `PulseOutOfRange` |
| 負荷のパルス名が解決できない（`w99c` など） | どのパルスにも負荷を入れず、警告なしに負荷がないものとして計算する | エラー `PulseOutOfRange`（負荷が有効なときだけ） |
| スタックしたアンテナで、パルス番号（`5` など）で指定した給電点・負荷 | 番号にもワイヤ番号と同じくコピーごとのワイヤ本数を足すので、2 つ目以降のコピーの分が 1 つ目のコピーの別のパルスに付く（10 分割のダイポールを横に 2 つ並べ、中央の `5` に給電すると 5 と 6 に給電され、利得が約 5.38 dBi から 2.66 dBi に下がる） | 各コピーの同じワイヤの、始点から同じ位置のパルスに付く（例では 5 と 14。`w1c` と同じ）。1 つ目のコピーにない番号はエラー `PulseOutOfRange` |
| パルス番号・ワイヤ番号・オフセットが 2147483647 を超える（`4294967297`、`w4294967297c` など） | 32 ビットに切り詰めるので別の番号になる（`4294967297` はパルス 1） | 解決できない名前として扱う（給電点・負荷ではエラー `PulseOutOfRange`） |
| 給電点が 2 つ以上、同じパルスに解決される（`w1c` と、その番号など） | 励振は加算ではなく代入なので、後の給電点が前の給電点を上書きする。各給電点のインピーダンス・電力は「自分の電圧 ÷ 後の給電点による電流」になり、合計電力が負になることもある | エラー `DuplicateSource`（給電点の番号とパルスを示す）。負荷は加算されるので、同じパルスに複数あれば直列として計算する |
| 大地ありで、地平線より下の方向の遠方界（天頂角 90° を超え 270° 未満。遠方界ファイル・API で指定したとき） | 鏡像を含めて計算した値を出す（地中の利得になる） | 放射なしとして −999 dB（NEC-2 と同じ扱い）。MMANA 本体の指向性図は地平線より上しか使わないので、利得・F/B・パターンは変わらない |
| 入力電力が 0 以下になる（2 本のワイヤが鋭角に交わる、接続点で線径が大きく違う、など MININEC の手法が破綻する形） | そのまま結果を出す。利得はすべて −999 dBi になる | 同じ結果に警告を付ける。近傍界は入力電力で正規化するので、エラー `NonPositivePower`（旧版は NaN） |
| つながった別のワイヤーが区間の横を通る（折り返しダイポールの端、約 27° より鋭い V の頂点） | 横の点を区間上の点として近似したまま計算する（折り返しダイポールで共振が +6〜16 % ずれる） | 同じ結果に警告 `CloseWires` を付ける（区間が点までの距離の 4 倍以上で、λ/250 より長いとき。[測定](measurements/README.md)） |
| つながった 1 つの導体の分割数が約 250 を超える | 分割を増やすほど結果がずれる（半波長ダイポールの 320 分割で X が約 6 Ω） | 同じ結果に警告を付ける |
| 入力は有限でも、結果が表せない大きさになる（電圧 1e100 で表示用電流が f32 を超える、近傍界の電力 1e308 など） | 無限大・NaN のまま結果を出す | エラー `NotRepresentable`（何の値かを示す） |
| 集中定数の L と C がともに 0 | X = −1 ÷ 0 になり、電流が NaN のまま結果を出す | エラー `InvalidLoad` |
| S パラメータ形式の負荷で、分母の係数がすべて 0（係数がない場合を含む） | 0 ÷ 0 の NaN のまま結果を出す | エラー `InvalidLoad` |
| S パラメータ形式の負荷が 13 項以上（JSON・API からのみ入力できる） | 12 項までしか持てない | エラー `InvalidLoad`（以前の移植版は 13 項目以降を黙って捨てていた） |
| 有限でない値（NaN・無限大。`.maa` の数式 `1e999` などで生じる）、スタックの個数が 0 以下、範囲外の SWR 基準・F/B 範囲・大地の定数・水平パターンの仰角 | 計算を続け、NaN を含む結果や、原因と関係のないエラーになる | エラー `OutOfRange`（項目・範囲・値を示す）。範囲は [保証一覧](guarantees.md#入力の範囲) を参照 |
| 組み合わせワイヤの定義が見つからない | 警告を出し、そこで展開を打ち切って計算を続ける | エラー `CombinedWireNotFound` |
| 自動分割の SC が 1.01 未満、DM1・DM2 が 0 以下、EC が 0 以下（JSON・API からのみ入力できる） | 画面と .maa 読み込みでは範囲内に補正されるが、そのまま計算すると分割処理が終わらない（SC は 1 をわずかに超える値でも終わらない） | エラー `InvalidAutoSegmentation` |
| ワイヤ個別テーパの DM が 1〜32767 の範囲外（DM2 なしの DM1 は 1〜10000） | DM2 が 0 だと分割処理が終わらない | エラー `InvalidWireSegmentation` |
| 固定分割数が 0 以下（JSON・API からのみ入力できる） | SEG の値として自動分割やテーパの指定に読み替えられ、DM2 が 0 になる値では分割処理が終わらない | エラー `InvalidSegmentCount` |
| 自動分割の分割数が 65536 以上になる（DM2 を大きくした長いワイヤなど） | 偶数に丸めるときに下位 16 ビットだけを残すので、1 波長のワイヤで DM2 = 65536 だと 4 分割（3 パルス）になり計算が進む | 偶数への丸めだけを行い、パルス数の上限でエラー `TooManyPulses` |
| 展開ワイヤが 4096 本を超える | 超えた分を黙って捨てる | エラー `TooManySegmentWires`。スタックは、コピー数 × R ≠ 0 のワイヤ本数が 4096 を超えるとコピーを作る前にこのエラーにする |
| 両端が完全に一致するワイヤが 2 本ある（向きは問わない。R = 0 の無効なワイヤは除く） | インピーダンス行列が特異になり、電流・インピーダンスが NaN のまま計算を続ける | エラー `OverlappingWires`（ワイヤ番号を示す） |
| それ以外の理由で解（電流・インピーダンス・SWR）が有限にならない（間隔 0 のスタックなど） | 同上 | エラー `NoFiniteSolution`。最適化中の試行でこうなったときは、そこで最適化を終える |
| パルス数の既定上限 | 1280（INI で変更可） | 4096（`CalcOptions.maxPulses`、上限 8192） |
| 近傍界（磁界）の計算後 | 実大地の媒質の高さを格納する配列を作業領域として上書きしてしまう | 配列を分けたので影響なし |
| 連続計算 | 前回の計算のパターン配列などが残る | 計算ごとに新しい状態で始める |
| 地面との接続（大地ありのとき） | 端の Z（地上高を足したもの）がちょうど 0 のときだけ接続する。計算で作った座標（極座標で天頂角 180° にしたワイヤなど）は −4.4×10⁻¹⁶ m になり、接地されない（Ewe で 486 Ω が 1.4 Ω になる） | ワイヤの長さの 10⁻⁹ 以内なら 0 として接続する。「地面の下」の警告も同じ許容誤差で出す |
| 積分の次数の切り替え（区間どうしの距離の比が 1.1 を超えると厳密な核をやめ、6・10 を超えると積分の次数を下げる） | 比をそのまま比べる。規則的な形では比がちょうどしきい値に乗り、座標の丸めでどちらになるかが決まる。座標が 1 ulp 違うだけで \|Z\| が最大 0.03 % 動き、最適化の試行を書き戻すと一覧の値にならず（0.47 % の例）、OS の libm でも結果が変わる | 比がしきい値を 10⁻⁹ 超えるまでは精度の高い側（厳密な核・元の次数）を使う。正解データを作るオラクルにも同じ変更を入れたので、比較はビット一致のまま。サンプル 149 件のうち 104 件のインピーダンスが変わり、最大 0.025 %（VERT58）、利得は 0.0004 dB 以内 |
| 入力抵抗が \|Z\| の 100 万分の 1 程度より小さい（入力電力が皮相電力の 10⁻⁶ 未満） | そのまま結果を出す。利得は入力電力で割るので丸めに支配される | 結果に警告を付ける（行列が `float` なので、それより小さな入力抵抗は丸めと区別できない） |

## ファイル（.maa）

| 項目 | オリジナル | 移植版 |
|---|---|---|
| 数式の `R`（波長） | 読み込み時は常に 14.05 MHz の波長になる（初期化順の都合） | そのファイルの設計周波数の波長 |
| 設計周波数の小数点以下 4 桁目以降（手で編集したファイルなど） | 読み込み時に画面表示（`%.3lf`）を経由するため、0.001 MHz 単位に丸めて計算・保存する。DP20 を 14.05049 MHz にすると 77.627 − j5.341 Ω | 丸めずに計算・保存する。同じファイルで 77.632 − j5.292 Ω |
| SWR 基準の jX の保存 | `%.lf` で小数点以下を切り捨てて保存 | 小数も保存（読み込みは互換） |
| ワイヤ・給電点・負荷の数 | 512 / 64 / 100 で打ち切り | 制限なし（計算時の上限は上表のとおり） |
| パルス名の末尾の空白 | 名前の一部として扱い、解決に失敗することがある | 取り除く |
| 実大地の媒質・ラジアル | 保存しない（`Mmana.ini` に保存） | 既定値から変えたときはコメント欄に保存（下記） |
| ワイヤのメモ・グループ | なし | ワイヤごとに `番号=文字列`（パーセントエンコード）の行で、コメント欄の末尾の `[MMANA-WIRE-NOTES]`・`[MMANA-WIRE-GROUPS]` ブロックに保存。計算には使わない。オリジナルではコメントの文字として表示される |
| ファイルの文字コード | Shift_JIS のみ | Shift_JIS と UTF-8 を自動判別。保存は Shift_JIS が既定 |

## エレメント編集

受け付けた編集で書き戻すワイヤの座標・半径・分割数はオリジナルと完全に一致します（金型との比較は、下表の拒否をしない
`ElementList::apply_as_original` で行います）。違いは、壊れたアンテナを書き戻す編集を拒否すること、書き戻した後の扱い、上限・表記です。

| 項目 | オリジナル | 移植版 |
|---|---|---|
| ワイヤ番号が変わったときの給電点・負荷 | パルス名（`w3c` など）をそのまま残すので、別のワイヤを指すことがある。削除で空いた番号に新しいワイヤが入ると、そのワイヤに付く | ワイヤに追従して番号を書き換える。削除したワイヤ上のものは、空いた番号に別のワイヤが入っても引き継がず、取り除いて警告を出す。形式を作り替えたエレメントでは、古い k 本目のワイヤ上のものが新しい k 本目に移る（新しい形のワイヤが少なければ、余った分は取り除いて警告）。電圧自動設定が有効なら、給電点を取り除いたあと各電圧を 1 / 給電点数 にそろえる（給電点の削除と同じ扱い） |
| パルス番号（`15` など）で指定した給電点・負荷 | そのまま | そのまま。番号がずれうるので警告を出す |
| エレメント数 | 256 で打ち切り（グループ番号を 1 バイトで持つため、それ以上は誤動作する） | 制限なし（API は「(操作数 + 1) × ワイヤ数」を 100 万までに制限） |
| 水平△・水平▽ の作り替え | メニューの「水平▽」は、形式表で「水平△」と呼ぶテンプレートで作る（できた形は ▽ と判定される） | 作られる形で呼ぶ（`horizontalInvertedTriangle` を指定すると ▽ と判定される形になる）。同じ形式かどうかの判定はオリジナルと同じくテンプレートで行う |
| CSV ファイル | Shift_JIS。Seg. の `400,40` を引用符で囲まないので列がずれる | UTF-8（BOM 付き）。カンマを含む値は引用符で囲む |
| 同一エレメントの確認 | OK を押したときに警告 | 編集のたびに確認し、重なっている間は「反映」を押せない |
| 寸法・位置・ワイヤが有限でなくなる編集（幅 `f64::MAX` で全周が無限大になるなど） | 無限大・NaN のワイヤを書き戻す | 拒否する |
| 端の点だけを動かす寸法の変更で、端の点がエレメントの他の点を追い越す（延長線付きダイポールを延長線の付け根より狭くするなど） | 表には入力した寸法を出し、ワイヤは追い越された点までの幅のまま。動かしたワイヤが他のワイヤに重なる | 拒否する。寸法の変更・値を丸める・形式の作り替え・コピーのあと、表の寸法と位置がそのエレメントのワイヤの範囲と一致しなくなる編集はすべて拒否する（10 ppm、最低 0.01 mm まで。開いたときから一致していない軸は対象外） |
| 表の寸法がワイヤの範囲と一致しないエレメント（コーナーリフレクタの格子を幅が半分の 1 つの四角形と判定するなど）の、端の点だけを動かす変更 | 範囲の外の点を動かさず、形が崩れる | その軸を動かす編集は拒否する（「全ての座標を同一比率で変更」はできる） |
| ワイヤの長さが 0 になる編集（cm 単位に丸めて 4 mm のスタブが消える、Swiss Quad を八角形として作り直すなど） | 長さ 0 のワイヤを書き戻す（計算できない） | 拒否する |
| 「全ての座標を同一比率で変更」で原点をまたがないエレメントを拡大・縮小した後の、端の点だけを動かす変更 | 原点を基準に拡大・縮小するのに範囲は元の中心に残るので、端の点が見つからずに形が崩れる | 範囲を実際のワイヤの位置に合わせ直す（拡大・縮小そのものはオリジナルと同じ） |
| ワイヤとその逆向きのワイヤだけで閉じたエレメント（角がないループ） | 寸法が −∞ | ワイヤの範囲を寸法にする |
| mm 表示で「値を丸める」（小数点以下 4 桁） | `RoundUp` が `int` に変換するので、214.748 m を超える寸法・位置は桁あふれする（Windows では負の値になる） | 桁あふれせずに丸める |
| 波長表記・mm 表示の設定 | 波長表記は起動のたびに解除され、mm 表示は INI に保存 | どちらもブラウザ・アプリごとに保存し、ワイヤー表とエレメント編集で共有する。mm 表示が既定なのはオリジナルと同じ |
| 起動したときのアンテナ | 空（ワイヤー・給電点なし、名前なし）。大地は前回終了時の設定（INI）、初回は自由空間 | 14.05 MHz の半波長ダイポール（0.48 λ、半径 1 mm、SEG −1、中央に給電）、リアルグランド・地上高 20 m。開いてすぐ計算・表示できるようにするため。「新規作成」はオリジナルと同じく空になり、大地・地上高・線材は直前のものを引き継ぐ（SWR 基準と F/B 範囲は既定値に戻る） |

オリジナルの次の動作は、結果を変えないようそのまま再現しています。

- ループの判定は、意図とは違い常に 1 本目のワイヤから始まる（最長のワイヤを探す処理が働いていない）
- 「全ての座標を同一比率で変更」は、エレメントの中心ではなく原点を基準に拡大・縮小する
- 端の点だけを動かす横幅・縦幅の変更は、範囲が 0 から始まるか、0 をまたぐか、0 から離れているかで基準が変わる（0 を固定、0 を基準に比例、中心を固定）。
  0 から離れたエレメントを 0 をまたぐまで広げてから元の値を入れ直すと、中心ではなく 0 を基準に縮むので、元の位置には戻らない（「元に戻す」なら戻る）
- 八角形の全周を変えると、縦幅と横幅が違っていても正八角形に作り直す。縦横比の違う八角形の全周を変えてから元の値を入れ直しても、
  元の縦横比には戻らない（「元に戻す」なら戻る）。中心を基準に全体を拡大・縮小するよう変えるかを検討中（[#7](https://github.com/Ebycow/MMANA/issues/7)）
- 「値を丸める」で半径が 0 に丸まると、mm 表記では小数点以下 2・3・4 桁でそれぞれ 10 m・1 m・0.1 m になる（1/1000 の付け忘れ）
- 「新規」の行で形式を選んで作ったエレメントの間隔は 0（前に削除したエレメントの間隔が残っていればその値）になる
- 何も変更せずに OK したときは書き戻さない（書き戻すと X 座標に丸め誤差が入るため）

ダイアログのうち「電卓」（数値欄で数式が使えるので不要）、「組み合わせワイヤ設定」（編集画面が未移植）は移植していません。「印刷」は、ファイルメニューの印刷のエレメント表にまとめました。
最適化用の変数選択モード（`TGrpWireDlg::Select`）は、最適化の変数表の「位置」「箇所」のメニューに置き換えました（エレメントの形式も表示します）。

## 最適化

試す値の順序、評価値、試行の記録、最終的なアンテナはオリジナルと完全に一致します（バンドが 2 つまでで、下表の拒否・折り返しが起きない場合）。
違いは次のとおりです。

| 項目 | オリジナル | 移植版 |
|---|---|---|
| 3 バンド以上の評価値の合算 | 2 番目以降のバンドの代わりに最後のバンドの評価値を足す（`BV[b]` を `BV[bb]` と書くべきところ）。2 番目から最後の 1 つ手前までのバンドは評価されない | すべてのバンドを足す。2 バンドまでは同じ値 |
| 複数バンドで最適化した後の給電点と計算周波数 | 最後に計算したバンドのまま残る | 最適化前の給電点と計算周波数に戻す（周波数・給電点を変数にした場合はその最良値） |
| 最適化結果の一覧から反映（更新） | いまのアンテナからエレメントを解析し直して値を当てはめる。試行でエレメントの並びが変わっていると（間隔を負にして別のエレメントの後ろへ回したなど）、別のエレメントに当てはまる | 最適化を始めたときのアンテナと計算条件に当てはめる（その後の編集は失われる） |
| 最適化結果の一覧のパターン | 最後に計算したバンドのもの。1/256 dB の固定小数点 | 1 番のバンドのもの（一覧の数値と同じバンド）。`float` のまま |
| S パラメータ形式の集中定数を変数にする | エラーを表示するが、そのまま最適化する | 実行しない（`sDomainLoad`） |
| 存在しない変数への連携・`#n` | 連携は変数 1 などに黙ってつながる（未使用の行の内容による）。`#n` は配列の外を読む | 実行しない（`missingVariable`） |
| 給電点の変数が、給電点の少ないバンドにない | 給電点配列の使われていない領域に書き込んで続ける | 実行しない（`bandMissingSource`） |
| 存在しないワイヤ（極座標）・給電点を変数にする | 確認せずに配列の外を読み書きする | 実行しない（`missingTarget`） |
| 1 回も試行が終わらないうちに中止・計算エラーになった | 最良値の代わりに「開始値の符号を反転した値」をアンテナに書き込む | アンテナを変えない |
| 実行時に開始値を Min / Max に収める（`Check`） | 前回の実行の歩幅が残っていると、境界から歩幅だけ内側に収める | 常に最初の実行と同じ（境界そのもの）。設定がアプリの中だけにあり、前回の歩幅を持ち越さないため |
| 変数の挿入・削除 | 連携の番号は付け替えるが、Min / Max の `#n` は付け替えない | `#n` も付け替える（削除した変数を指していたものは数値の Min / Max に戻る） |
| 「全エレメント」で作る変数 | 前に使っていた行の `#n` が残ることがある | 残らない |
| ピッチ 0 の単純スイープ（ピッチが小さすぎて値が変わらない場合も） | 最大値に届かないまま同じ値を記録から読み続け、止まらない（中止もできない） | 値が動かない一歩を最大値・最小値に届いたものとして扱い、開始値を 1 回計算して終わる |
| 地中に埋まるワイヤ | 試行のたびに中止するか尋ねる | 続ける（計算結果に警告が付く） |
| 動かした順でアンテナが変わる変数の組（ワイヤの端とそのエレメントの幅、トラップの L と C、スローパーの上端を固定した天頂角と中央を固定した長さ、連携させたワイヤの X とそのエレメントの間隔など） | 実行する。試行の値の組から試行のアンテナが決まらないので、記録の評価値が別のアンテナに使われ、最後に書き戻すアンテナが最良とした試行と別物になる（jX −1.2 Ω の最良が −64 Ω のアンテナとして書き戻される例があった） | 実行しない（`overlapping`）。変数の組ごとに両方の順で設定してみて、結果が違えばこの扱いにする。ワイヤ（直交・極座標）の変数とそのワイヤを含むエレメントの変数は、常にこの組として扱う |
| 試す値で、エレメントの端の点が他の点を追い越す・範囲が 0 をまたぐ、ワイヤの端どうしが新たに一致する・離れる、ワイヤがアンテナの 10 億分の 1 以下に縮む、極座標の値が読み戻せない（天頂角が 180° を超えて方位角が反転する、0° で方位角が消える）、または値の組を最初のアンテナに設定した形と 10 ppm を超えて違う | そのまま試す。同じ値の組でも経路で形が変わり、記録の評価値・書き戻し・最後のアンテナが試行と食い違う | 範囲の端に当たったのと同じく、最良の値に戻って向きを変える |
| 入力電力が正でない、または皮相電力の 100 万分の 1 未満の試行（MININEC が破綻している、入力抵抗が計算の丸めの大きさ。計算結果に警告が付く） | 採点する。マッチング目標では NaN になり、利得は丸めで 1 dB 近く動く | 最低の評価値（`f64::MIN`）にし、最良に選ばない（単純スイープを除く） |
| 最後に最良の値を書き戻す順番 | 変数の番号順に 1 つずつ設定する。連動した変数のあいだに同じワイヤの変数があると（X1・X2 を連動させ、間に極座標の長さ）、傾いたワイヤに長さを設定するので、最良の試行と別の形になる | 探索と同じく、独立した変数ごとに、それに連動する変数と続けて設定する（`apply_trial` も同じ）。番号順と結果が同じ設定では一致する |
| 計算が失敗して止まったときの最後のアンテナ | 失敗したアンテナに最良の値を設定し直す | 最初のアンテナに最良の値を設定する（試行の書き戻しと同じ）。失敗したアンテナは長さ 10⁻¹⁵ m のワイヤなどで、設定し直すと別の点まで動くことがあるため |
| スタックしたアンテナの電流目標 | 展開前のアンテナのパルス番号で、展開後の電流配列を読む | 展開後のアンテナで解決する（`w1c` は 1 つ目のコピー） |
| 最適化シート（`.mao` / `.mao64`） | 保存・読み込みできる | 旧形式の入出力と、デスクトップでの設定・試行履歴の保存・復元は未対応。設定は新規作成・別ファイルの読み込み・アプリ終了まで保持。CLI は JSON の設定を読み込んで実行可能 |
| 実行中のログ | すべての計算を 1 行ずつ表示 | デスクトップアプリは評価値が上がった計算をすべて、それ以外を 40 ms ごとに表示。ブラウザ版は終了後の一覧のみ |

オリジナルの次の動作は、結果を変えないようそのまま再現しています。

- 連携が連携先を経由して続くときは、最後に到達した独立変数に、自分の連携式だけを適用する（途中の連携式は使わない）
- ワイヤの X 座標（X1, X2）の変数は、最初のエレメントが見つかった位置から数えた位置に足す（最初のエレメントを動かす変数との組は、上表の `overlapping` になる）
- ワイヤの座標を変数にしても、エレメントの境界は解析し直さない（同じエレメントの寸法の変数との組は、上表の `overlapping` になる）
- 目標なし（単純スイープ）は、各変数を現在値から最大値まで動かしたあと、現在値から最小値までも動かす。評価値はすべて −0.1
- 複数バンドのとき、周波数の変数は 1 番のバンドの周波数を変える。給電点の変数はバンドの給電点で上書きされるので効かない
- 試行の記録は直近 128 件で、同じ値の組み合わせが記録にあれば計算せずにその評価値を使う

## 共振周波数の探索と推測計算

周波数特性ダイアログ（`BwDisp.cpp`）の「共振周波数を計算」（`GetFoBtnClick`）と推測計算（`CalcSim`）を移植しました。

- **推測計算**は、jX が 0 に近い 2 点から、アンテナを直列 RLC 回路とみなして L・C・Q・共振周波数・帯域幅を求めます。式はオリジナルと同じです。
  - オリジナルは L・C の絶対値を取るので、リアクタンスが周波数とともに減る区間（反共振の付近）でも値を出します。移植版はその場合は値を出しません（直列回路の前提が成り立たないため）。
  - オリジナルは、計算していないスイープ点の R・jX もこの回路で埋めて表示します。移植版のスイープは全点を計算するので、この補間は移植していません。
- **共振周波数の探索**の手順を変えました。止まる条件（|jX| < 0.1 Ω）と、探す範囲（開始周波数の半分〜2 倍）はオリジナルと同じです。
  - オリジナル：ダイアログのスイープの中心を推測した共振周波数に移し、幅を狭めながら最大 20 回スイープします。中心は 1 kHz 単位に丸め、推測値の動きが 0.1 % 未満になったときにも止まります。
  - 移植版：計算周波数から、リアクタンスの符号が示す向きに進みます（誘導性なら下へ、容量性なら上へ）。符号が変わったら、その区間を推測計算の値か二分で狭めます。給電点のインピーダンスだけを計算するので（パターンは求めない）、1 回の探索はサンプルで 3〜9 回の計算です。
  - 移植版は |jX| < 0.1 Ω まで詰めるので、共振周波数はオリジナル以上に X = 0 に近くなります（半波長ダイポールで 0.01 % 以内をテストで確認）。
  - 自動分割の分割数が周波数で変わり、リアクタンスが 0 をまたいで跳ぶ場合は、跳ぶ位置を返して `converged: false` とします。同梱のサンプルでは起きませんでした。

## 印刷

オリジナルの 3 つの印刷を、ファイルメニューの「印刷」の 1 つの書類にまとめました。どれを含めるかは印刷のプレビューで選びます。

- **パターン図**（`TMainWnd::PrintBtnClick`）：水平・垂直の指向性図と、その下の結果欄（`CRes::DrawRes`）を同じ内容で印刷します。結果欄の Gh（dBd）を自由空間のときだけ出すこと、SWR を基準インピーダンスと 600 Ω の 2 つで出すこと、打ち上げ角と水平パターンの仰角が違うときにその仰角と最大利得を出すことも同じです。
- **エレメント一覧**（`TGrpWireDlg::K14Click`）：オリジナルと同じく、位置と間隔の両方の列を含むエレメント編集の表を印刷します。
- **周波数特性**（`TBwDispDlg::PrintBtnClick`）：SWR・インピーダンス・利得・F/B のグラフと、SWR < 1.5・< 2.0 の帯域幅（`GetSWRWidth`：SWR 最小の点から両側へ、上限を超える点との間を線形補間）を印刷します。帯域がスイープの端まで続くときは、オリジナルは端までの幅をそのまま出しますが、移植版は「≥」を付けます。推測計算の L・C・Q・帯域幅・共振周波数（`DrawConst`）は、共振点を探したときに印刷します。整合回路を適用した特性は、その画面が未移植なので印刷しません。

## 計算環境の値

実大地の媒質（誘電率・導電率・境界・高さ）とラジアル設定は、オリジナルでは `.maa` ではなく `Mmana.ini` に保存されています。
このため、オリジナルでは同じファイルでも PC ごとに計算結果が変わりえます。
移植版では `Environment.realGround` に持たせ、既定値はオリジナルと同じ（誘電率 5、導電率 0.001 S/m、媒質 1 つ）です。

既定値から変更した場合は、`.maa` のコメント欄の末尾に次のブロックとして保存します（ワイヤのメモの `[MMANA-WIRE-NOTES]` と同じ方式です）。

```
[MMANA-REAL-GROUND]
medium=誘電率,導電率,境界,高さ
screen=ラジアル本数,ラジアル半径
[/MMANA-REAL-GROUND]
```

- `medium` は媒質ごとに 1 行です。境界・高さは未設定なら空欄にします。`screen` はラジアルを使うときだけ書きます。
- 既定値のときはブロックを書かないので、オリジナルが書くファイルと同じ内容になります。
- 移植版は読み込み時にブロックを取り除き、値を計算環境に戻します。読めないブロックや閉じていないブロックはコメントのまま残し、警告を出します（大地は既定値になります）。
- オリジナルで開くと、ブロックはコメントの文字として表示されます。計算には使われず、オリジナル自身の INI の値で計算されます。
